## Evidence, market scan, capability freshness, alternatives, and grilling

The accepted evidence, primary-source market scan, main recommendation, two
rejected/deferred alternatives, capability-map state, V1/non-goals, acceptance
plan, and eighteen resolved `$grill-me` branches are recorded in ADR 0004 and
the immediately preceding decision log and remain unchanged.

The product stage moved from an inspectable Agent Artifact plus protected
source-started Server to the first clean-host deployment boundary. Current
source, git state, the capability map, the three preceding item-08 logs, Bun
and OCI primary sources, package scripts, the example Agent, and real CI
container logs were inspected during implementation.

The relevant capability-map entry remained `confirmed` throughout. It is now
updated from approved/pending to shipped; Agent Definition and Independent
Serving remain confirmed without changing their Pi event or Session contracts.

Candidate opportunities remained:

1. Main recommendation: the approved project-specific, engine-neutral Agent
   Deployment Image context.
2. Rejected: copy source and install dependencies inside a generic Bun image.
3. Deferred: a generic Server image plus mounted executable artifact/registry.

The main recommendation won because it is the smallest complete operator job:
build one immutable Agent, inject only declared runtime values, mount one
single-writer path, observe readiness, and stop/recreate without losing the
Session. V1 excludes cloud control planes, registries, managed secrets,
distributed storage, autoscaling, signing/attestation, and a new protocol.

Acceptance required deterministic context bytes, safe startup failures,
package/repository gates, and actual amd64/arm64 containers proving
health/readiness, authenticated persistence, non-root volume behavior,
single-writer/artifact rejection, SIGTERM, and one two-platform index. The
approved `$grill-me` discussion had already resolved all eighteen material
artifact, secret, network, ownership, lifecycle, and CI branches; no new branch
or scope change appeared during implementation.

## Work performed

- Added validated, deeply immutable `defineAgent().environment` requirements
  whose config/secret names and classifications join the item-05 artifact
  identity without carrying values. Runtime and TypeScript fixtures reject
  invalid names/kinds, defaults, duplicates, and Host-variable collisions.
- Added a deterministic closed Agent bundle that captures two project copies,
  preserves tools, MCP auth/header callbacks and skills, embeds the complete
  artifact descriptor, rejects non-literal runtime loading and unresolved
  external imports, and does not retain source roots or source maps.
- Added the engine-neutral `llm-space build [directory] --target oci --output`
  command with sibling staging, overwrite refusal, locked Bun compiler/base,
  source revision label when available, environment manifest, protected
  bootstrap, health probe, and fixed `Containerfile`.
- Made the bootstrap validate artifact section/overall hashes, environment
  fingerprints, Host topology, principal structure, required Agent input, and
  runtime secret absence before authored import. Server auth is removed from
  `process.env` first; errors expose only a sanitized startup stage.
- Reused the protected Server with the narrow ADR-0004 loopback exception for
  health/readiness. Business routes retain trusted-proxy, HTTPS, Host,
  principal, continuation, and Session authorization.
- Added the fixed `0.0.0.0:7331`, UID/GID `1000:1000`,
  `/var/lib/llm-space`, readiness, `SIGTERM`, and eight-second drain image
  profile, plus complete operator documentation for Docker Buildx, Podman,
  Buildah, proxy forwarding, bind-mount ownership, and stop grace.
- Added a Bun-driven OCI acceptance driver and non-release workflow. Initial
  runs exposed and fixed explicit `Containerfile` selection, empty optional
  credential normalization, and a non-canonical continuation fixture. The
  product contract was unchanged by those CI fixes.

## Review

The required two-axis review used fixed point `0461c6c`. Standards review first
found sentence-case/private/generated-constant naming issues; Spec review found
missing production external-import rejection, ineffective secret proof, and
missing MCP callback proof. All hard findings were fixed and the final targeted
reviews report zero hard Standards findings and zero Spec findings.

Two judgement-only duplication smells remain intentionally local: Runtime and
CLI each own a fresh-Bun-process bundling adapter, and the bootstrap carries its
small canonical-JSON verifier rather than importing the compiler graph before
authored code. Extracting either would weaken the package or initial-module
boundary for no V1 behavior gain.

The Docker Actions setup emits a non-failing Node 20 deprecation warning while
GitHub forces it to Node 24. This is future workflow maintenance, not failed
acceptance. No secret, token, raw auth header, or private payload is recorded.
